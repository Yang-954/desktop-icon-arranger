# 移植笔记 —— 从 Python 版迁到 Rust 版

v2 (Python/PySide6) → v3 (Rust/Tauri 2) 过程中踩到的坑。
每一条都写进了对应代码的注释里, 这里留一份索引方便查阅。


全部写进了对应代码的注释里, 这里列个索引:

### 1. `DESKTOP_ALL` 漏了 `DESKTOP_CREATEWINDOW`

手写 `SWITCHDESKTOP | READOBJECTS | WRITEOBJECTS | HOOKCONTROL | ENUMERATE` = `0x014D`,
漏掉 `DESKTOP_CREATEWINDOW (0x0002)`。后果: 切桌面后 `CreateWindowExW` 返回
`E_ACCESSDENIED`, 表现为 Tauri 报 `failed to create window`。

**解法: 直接用字面量 `0x01FF`, 不手工拼装 —— 拼装必然漏位。**

### 2. 拼音排序的元素粒度

Python 的 `pypinyin.lazy_pinyin` 把**连续的非汉字当作一个元素**:
`"dsh-startup"` → `["dsh-startup"]` (1 个), 不是逐字符。

粒度不同直接导致排序结果不同 —— `"电脑配置.docx"` 首元素是 `"dian"`,
而 `"dsh-startup"` 首元素是 `"dsh-startup"`。

### 3. `sorted(reverse=True)` 是整体反转

Python 的 `sorted(key=(a, b), reverse=True)` 是「按 `(a,b)` 升序排, 然后整体反转」,
**不是**「按 a 降序、b 降序」。

所以 `time_desc` 模式必须用 `-mtime` 作为主键 (而不是 `mtime` 再反转)。

### 4. `Path.suffix` vs `Path::extension()`

Python 的 `Path.suffix` **带点号** (`".lnk"`), Rust 的 `Path::extension()` 不带 (`"lnk"`)。
写错会导致所有 `.lnk` 快捷方式被归类成"普通文件", 排序结果大乱。

### 5. 数字段解析漏掉第一个字符

外层循环已经消费了第一个数字字符, 内层循环从下一个开始收集 ——
结果 `"2"` 变成空串、`"10"` 变成 `"0"`。

### 6. `SHGetFileInfoW` 传 PIDL 在 windows crate 里不可行 —— 自己声明一个

crate 的 `SHGetFileInfoW` 第一个参数是 `PCWSTR` (字符串指针), **无法传 PIDL 指针**。
而回收站 / 控制面板这类虚拟目录**必须走 PIDL** 才能拿到正确图标。

**解法: 用 `unsafe extern "system"` 自己声明一个原始签名**
(`src/icons.rs` 的 `SHGetFileInfoW_raw`, 第一个参数是 `*const c_void`),
绕开 crate 的封装限制 —— 这样回收站 / 控制面板 / 网络 都能取到真实图标。

### 7. `SHGFI_USEFILEATTRIBUTES` 会让所有文件返回同一个默认图标

实测 4 个不同的 exe 提取出的 PNG 完全相同。去掉这个 flag 才正常。

### 8. 图标渲染必须用 `hbmMask` + `hbmColor` 配对

只画 `hbmColor` 会丢透明通道; 只用 `DrawIconEx` 画 `HICON` 得到的图也区分不出来。
正确做法是 `GetIconInfo` 拿到两个位图, 先画掩码再叠加彩色, 缩放用 `StretchBlt`。

### 9. PNG 压缩不能依赖系统的 `zlib1.dll`

实测本机 `C:\Windows\System32\zlib1.dll` **根本不存在**。改用纯 Rust 的 `flate2`。

### 9b. 图标必须返回完整 data URL, 不能只给裸 base64

`encode_png` 一度只返回裸 base64, 缺 `data:image/png;base64,` 前缀 ——
前端拿到后**直接塞进 `<img src="...">`**, 浏览器把裸 base64 当成**相对路径**请求 → 404 →
界面显示成空方框。**后端日志一切正常, 单元测试也全绿, 但界面是坏的。**

更隐蔽的是: 当时的测试用 `trim_start_matches("data:image/png;base64,")` 取 body,
**恰好把缺前缀这个唯一的 bug 掩盖成假阳性**。测试辅助函数越宽容, 测试越瞎。
现在有独立的 `提取结果带data_url前缀` 断言盯着它。

### 10. `windows_subsystem` 是编译期的, 没法按参数切换

想要"双击无黑框 + 命令行有输出", 一个 exe 做不到:
- `windows_subsystem = "windows"` → CLI 没 stdout
- 保留 console → 双击弹黑框

而且在 **Windows Terminal (ConPTY)** 下, `GetConsoleWindow()` 返回的是**伪句柄**,
`ShowWindow` 对它无效 —— 靠"运行时隐藏控制台窗口"这条路在 Terminal 里根本走不通。

**正解: 拆成两个二进制**, 各自用合适的子系统。
副作用: 必须给 GUI 那个 bin 加 `required-features = ["gui"]`,
否则 `cargo test --no-default-features` 会把它覆盖成 0.1 MB 的空壳。

### 11. Tauri 2.12 的 `withGlobalTauri` 在本机不生效

`app.withGlobalTauri = true` 本该注入 `window.__TAURI__`, 但实测 `window.__TAURI__` 为 `undefined`。

根因: 全局 API 脚本清单由 `tauri-build` 写进**app 包**的 `OUT_DIR`,
而 `tauri-codegen` (proc-macro) 从**它自己的** `OUT_DIR` 读
(`ensure_out_dir()` 取的是 proc-macro 的 OUT_DIR) —— 两者不是同一个目录,
`plugin_global_api_scripts` 因此是 `None`。

**绕过: 只依赖 `window.__TAURI_INTERNALS__`。**
它由 `core.js` (IPC 初始化脚本) **总是**注入, 提供底层原语
`invoke` / `transformCallback` / `registerCallback` / `runCallback`。
本项目的 QWebChannel 兼容层因此**自己实现了** `invoke` 与事件订阅
(`plugin:event|listen` + `transformCallback`), 不碰 `window.__TAURI__`。

### 12. 图标缓存的 key 不能在两处各算一半

图标缓存 key 的**读**用 `kind_raw` (`"SYS"`)、**写**用 `cat` (`"system"`) ——
两个值天然不同, 结果缓存**永远不命中**。
表现是"点刷新后图标全没了": 每次刷新都返回一份 icon 为空的骨架, 前端用它渲染就把图标抹了。

**解法: 让构造函数把 key 一并产出** (`build_items` 返回 `(items, cache_keys)`),
调用方直接拿去写 —— 从结构上杜绝分叉, 而不是靠"两边记得写对"。

顺带还有个竞态: 主线程原本在 `spawn` **之后**才写 `cached_items`,
会覆盖后台线程刚填进去的 icon —— 把缓存更新挪到 `spawn` 之前即可。

### 13. Shell / GDI 图标 API 不是线程安全的

`SHGetFileInfoW` / `ExtractIconExW` / `GetIconInfo` / `CreateDIBSection` 都会用到进程级的临时状态,
并发调用会互相破坏 HICON 句柄 (表现: 4 个不同的 exe 提取出同一张图)。

**锁必须覆盖"取句柄 → 渲染 → 销毁"的整个流程** —— 只锁渲染那一段不够,
句柄在锁外就已经被别的线程的 `DestroyIcon` 干掉了。
